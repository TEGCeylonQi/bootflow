# BootFlow

Windows 启动项体检与编排工具。把散落在注册表、启动文件夹、计划任务、服务里的开机自启项统一收拢，看清它们，然后编排它们。

**当前版本：v0.2.0** — 启动项开关可改、可快照、可一键回滚，回滚还有不依赖本软件的独立脚本兜底。程序**不请求提权、不弹 UAC**，按当前用户权限运行；只有分段耗时与「启动影响」需要管理员，读不到时界面会如实说明并给出提权入口。发现新版本时可直接在程序内下载安装，下载显示真实进度。

---

## 为什么做

Windows 的启动项散落在至少八个位置，现有工具（Autoruns、Process Lasso、任务管理器）都只覆盖一段。

## 能做什么

- **全来源扫描**：启动文件夹（用户级 + 全局）、Run / RunOnce（HKCU / HKLM / WOW6432Node）、Boot/Logon 计划任务、开机服务（含延迟启动与触发器）、系统注入（AppInit_DLLs / IFEO）
- **无效项检测**：指向已卸载程序的残留、重复入口、指向不可达位置的项
- **处置建议**：每项给出「建议清理 / 建议停用 / 建议确认」及一句话理由
- **开机耗时拆解**：读系统性能日志，拆到各阶段，列出慢启动服务
- **单项开销**：Windows 自己在登录窗口里为每一项量出的 CPU 时间与磁盘读写量，按与任务管理器相同的阈值分档——**可以打开任务管理器逐条对照**
- **跨来源去重**：同一程序多处注册时识别出来
- **三层风险评级**：禁改区 / 高危 / 注意 / 安全，并附判定依据
- **写能力（可逆）**：想改的项先进变更篮 → 应用前 Dry-run 预演（改动前/后、一句话后果、风险）→ 逐项护栏 + 乐观锁 → 执行即建改前快照，可一键回滚；中途失败自动退回已改部分，不留「改了一半」
- **报告导出**：JSON / CSV / Markdown
- **更新检测**：启动后自问一次，顶栏常驻入口；检查失败如实报告，不谎报「已是最新」

### 界面

键盘可用：`↑↓` 移动、`空格` 勾选、`/` 搜索、`1/2` 切视图、`Esc` 逐层退出。

名称统一识别：界面上显示从程序元数据读出的产品名，不暴露原始文件名 / 注册表值名 / 任务路径（这些在「技术详情」里可查）。

| 环境 | 状态 |
| --- | --- |
| Windows 11 (21H2+) | 已实测 |
| Windows 10 1809+ | 支持，未实测（事件日志 schema 有差异，解析按可选字段容错） |

## 关于权限

- **程序不请求提权，也不弹 UAC**。exe 的 manifest 是 `asInvoker`，以启动它的那个用户令牌运行；安装包是用户级安装（`currentUser`），不需要管理员
- **这不是能力妥协，是刻意的取舍**。核心功能在普通权限下就完整可用：启动项全量扫描、风险评级、诊断建议，以及每次开机的总时长——后者读的是 System 通道的开机事件，该通道 ACL 允许普通用户读
- **只有两层数据需要管理员**：分段耗时（`Microsoft-Windows-Diagnostics-Performance/Operational`）与「启动影响」（WDI `StartupInfo`），这两个通道的 ACL 只给了管理员。读不到时界面会写明原因，并提供「以管理员身份重开」入口，**不带伪造精度**
- **为什么不直接声明提权**：管理员账户下 `highestAvailable` / `requireAdministrator` 会让**每次双击都弹一次 UAC**；受限令牌环境（脚本、CI、被沙箱限制的 shell）会直接启动不了；放进开机自启时登录过程也弹 UAC，用户必然去关掉自启。**默认永不弹 UAC 是硬约束。**

## 安装

从 [Releases](https://github.com/TEGCeylonQi/bootflow/releases) 下载 `BootFlow_x.x.x_x64-setup.exe`（NSIS 安装包，用户级安装）。

运行依赖：[WebView2 运行时](https://developer.microsoft.com/microsoft-edge/webview2/)（Win11 与较新 Win10 已内置，更早系统安装包会自动提示下载）。

## 已知限制

- **开机耗时需要管理员权限**。普通权限下读不到，界面会明确写「未读取」并给原因，不会显示成 0 秒或空图
- 计划任务个别 ACL 受限会跳过并在结果里列出
- 目标位于断开的网络共享 / 已拔出介质 → 标为「位置当前访问不到」，插回来就恢复，不是失效项
- 开机性能日志是 Windows 按需写的：**正常速度的开机可能什么都不记**。没有记录 ≠ 没有耗时
- **写能力尚未在真机上走完一次完整的「写入 → 回滚」闭环**（写入模块的测试全部是纯逻辑，不触真实系统）。界面与命令都已接通，但首次使用建议先在虚拟机里试；这一项验证完会从本列表移除

## 架构

**原生 Windows 桌面应用**（不是网页）。界面由系统 WebView2 渲染（HTML/CSS），但整个程序是一个独立 `.exe`，双击即运行。

```
┌───────────────────────────────────────┐
│  BootFlow.exe（单个原生可执行文件）     │
│ ┌─────────────────┬─────────────────┐ │
│ │ Rust 主体        │ WebView2 渲染层  │ │
│ │ 扫描 / COM /     │ React UI        │ │
│ │ Win32 / 分析     │ 图表 / 交互      │ │
│ └─────────────────┴─────────────────┘ │
│         ↑ Tauri IPC（进程内通信）       │
└───────────────────────────────────────┘
```

- **前端**：React 19 + TypeScript + Vite + Tailwind，图表 ECharts
- **后端**：Rust + `windows-rs`，直调 COM 与 Win32（不用 `schtasks` / `sc` 命令行封装）
- **关键模块**：
  - `scanners/` — 五个来源扫描器，只负责「把原始记录读出来」
  - `diag/` — 开机日志解析、耗时归因、风险判定、诊断码表
  - `pipeline.rs` — 后处理流水线：身份归一 → 类型 → 有效性 → 去重 → 耗时 → 风险 → 建议（顺序即依赖）
  - `valid.rs` / `advise.rs` / `dedupe.rs` — 无效检测 / 处置建议 / 去重
  - `util/sign.rs` — 签名验证（内嵌失败查 catalog 目录签名，系统文件大多是后者）
  - `update.rs` / `util/http.rs` — 更新检测（WinHTTP，零新依赖）+ 发布页白名单

## 关于数据精度

不伪造精度。**「什么时候出现」「占了多少资源」「花了多久」是三个不同的量**，
来自四条互不相干的通路，界面分开陈述，任何情况下不合成一个数字：

| 量 | 来源 | 说明 |
| --- | --- | --- |
| 出现时刻 | 内核记录的进程创建时刻 | 实测。**不是耗时** |
| 启动影响 | Windows 诊断基础架构（WDI `StartupInfo`） | 实测。CPU 时间与磁盘读写量，与任务管理器同源同阈值 |
| 耗时 | 系统事件日志（EventID 101/102/103） | 实测。**只有被判慢的项才有** |
| 启动阶段 | 开机相位 | 估算，界面明确标注，不给时长 |

> 任何声称能精确给出「每个启动项花了 X 秒」的工具都在编：Windows 不为自启动项
> 记录**墙钟耗时**。能实测的是**资源占用**（CPU 时间/磁盘 IO）——多线程程序的
> CPU 时间跨核累加，可以超过窗口本身长度，所以它从不被当作耗时来展示。

| 版本 | 内容 | 原则 |

| v0.1.x | 早期只读阶段：全来源发现 + 诊断 + 报告 + 更新检测 | 零风险 |

**永久护栏**：

- 禁改区（服务栈 / Winlogon / explorer / 安全中心 / 驱动）不提供写入口
- 进程优先级 `RealTime` 永久禁止设置
- 打包永久 unpackaged，不用 MSIX

## 发布新版本

发布由 tag 触发，**不需要本地构建**：

```bash
# 1. 改三处版本号（必须一致，`npm run check` 会校验）
#    src-tauri/Cargo.toml · src-tauri/tauri.conf.json · package.json

# 2. 提交推送
git commit -am "chore: 版本号 X.Y.Z"
git push origin main

# 3. 打 tag 推
git tag vX.Y.Z
git push origin vX.Y.Z
```

三处必须一致：安装包版本来自 `tauri.conf.json`，程序内「当前版本」读 `Cargo.toml` 编进二进制的那个。不一致时，用户刚装上的新版会被自己的更新检测反复提示「有新版本」。

之后 CI 自动编译、创建 Release、上传产物：
`BootFlow_X.Y.Z_x64-setup.exe`（安装版）+ `bootflow-portable-x64.zip`（便携版）。

发布前确认：clippy 无警告、cargo test 全绿、check 与 ui:smoke 通过、**没有本机信息**（提交信息 / 示例数据 / 注释）。
